# 치지직 통합 녹화·VOD 다운로드 개발 명세

# E01. VOD URL 하나를 실제 파일로 다운로드

이 Epic이 끝나면 사용자는 프로그램을 실행하고 치지직 VOD URL을 분석한 뒤 품질과 폴더를 선택해 실제 파일을 다운로드할 수 있다.

## S01.1 사용자는 VOD URL을 입력해 영상 정보를 확인한다

### T0101. 실행 가능한 최소 메인 창

- **입력:** 프로그램 실행.
- **동작:** URL 입력칸, 분석 버튼, 분석 결과 영역, 작업 목록 영역, 설정 버튼이 있는 PyQt6 메인 창을 연다.
- **출력:** 분석 결과 영역에는 `치지직 VOD URL을 입력하세요`, 작업 목록에는 `작업 없음`이 표시된다.
- **성공 기준:** 한 개의 메인 창이 오류 없이 열리고 URL 입력과 분석 버튼을 사용할 수 있다. 아직 구현하지 않은 채널·알림·시스템 영역은 빈 자리나 동작하지 않는 버튼으로 미리 만들지 않는다.

### T0102. URL 입력 정리와 VOD 판별

- **입력:** 사용자가 입력한 URL 문자열과 분석 버튼 클릭.
- **동작:** 앞뒤 공백과 줄바꿈을 제거하고 치지직 VOD URL인지 확인해 VOD ID를 추출한 뒤, 치지직 VOD API를 직접 요청해 실제 제목을 확인한다.
- **출력:** 정상 VOD는 `VOD 정보 확인 성공`, 실제 제목과 VOD ID가 표시된다. 빈 값·다른 사이트·유사 도메인·ID 없는 URL은 `지원하지 않는 URL`, 네트워크·서버·응답 오류는 `VOD 확인 실패`와 이유가 표시된다.
- **성공 기준:** URL 입력만으로 다운로드나 채널 등록이 시작되지 않는다. 잘못된 입력은 네트워크 요청 없이 실패 이유가 표시된다. 정상 URL은 실제 API 응답의 제목과 VOD ID가 표시되고 API 요청이 실패해도 앱은 종료되지 않는다.

### T0103. VOD 정보 조회용 yt-dlp 확인

- **입력:** 앱에 의존성으로 포함된 yt-dlp Python 패키지와 T0102의 직접 VOD API 조회 기능.
- **동작:** yt-dlp 공식 Python API를 불러와 사용 가능 여부와 버전을 확인하고, 직접 VOD API 요청을 `extract_info(download=False)` 기반 조회로 교체한다.
- **출력:** 사용할 수 있으면 버전을 확인한 뒤 기존과 같은 실제 VOD 제목을 표시하고, 불러올 수 없으면 도구명과 설치 오류를 표시한다.
- **성공 기준:** 정상 URL의 제목 조회가 yt-dlp 공식 Python API를 통해 동작하고 T0102의 직접 치지직 API 의존은 제거된다. 패키지가 없거나 불러오기 오류가 발생해도 앱은 종료되지 않고 해당 분석만 실패한다. 사용자가 별도의 yt-dlp 실행 파일 경로를 선택하거나 저장하지 않는다.

### T0104. VOD 분석 결과 카드

- **입력:** yt-dlp가 반환한 VOD 정보와 품질 목록.
- **동작:** VOD 정보를 분석 결과 카드에 반영한다.
- **출력:** 썸네일, `VOD`, 제목, 채널명, 게시·방송 일시, 전체 재생 시간, 카테고리, 태그, 실제 제공 품질과 `다운로드 설정` 버튼이 표시된다.
- **성공 기준:** 조회 결과와 화면값이 일치한다. 없는 썸네일은 기본 이미지, 없는 카테고리·태그는 `정보 없음`으로 표시된다. 분석 결과에는 채널 등록이나 녹화 버튼이 없다.

### T0105. VOD 분석 진행·취소·오류

- **입력:** 분석 중 취소 버튼 또는 네트워크·인증·삭제·비공개 오류.
- **동작:** VOD 분석을 GUI 이벤트 루프와 분리해 실행하고, 분석 경과 시간을 갱신하며, 같은 URL의 중복 요청을 막고 취소 결과나 오류를 분석 결과 영역에 반영한다.
- **출력:** 분석 중에는 spinner, 경과 시간과 취소 버튼이 표시된다. 실패 시에는 오류 종류·설명과 `다시 시도`, `쿠키 설정`, `URL 수정` 중 가능한 행동이 표시된다.
- **성공 기준:** 분석 중 경과 시간이 계속 갱신되고 GUI 입력과 화면 갱신이 멈추지 않는다. 분석이 끝나거나 취소되면 시간 갱신도 종료된다. 취소한 요청의 늦은 결과가 화면을 덮어쓰지 않는다. 실패 후 다른 URL을 정상 분석할 수 있다.

## S01.2 사용자는 인증이 필요한 VOD를 위해 쿠키를 등록한다

### T0106. 쿠키 파일·문자열 등록

- **입력:** 쿠키 파일 또는 GUI에 붙여 넣은 쿠키 문자열.
- **동작:** 형식을 확인해 치지직 요청에 사용하고 입력 원문은 저장 완료 화면에 표시하지 않는다.
- **출력:** `쿠키 등록됨`, 읽은 항목 수 또는 형식·파일 오류가 표시된다.
- **성공 기준:** 빈 값·읽기 불가·지원하지 않는 형식은 저장되지 않는다. 쿠키값을 코드에 직접 입력하지 않고 GUI에서 교체할 수 있다.

### T0107. 인증 확인과 쿠키 삭제

- **입력:** 저장 쿠키와 인증 확인·삭제 버튼.
- **동작:** 인증이 필요한 조회로 상태를 확인하거나 쿠키를 제거한다.
- **출력:** `인증됨/만료/잘못된 쿠키/네트워크 오류/쿠키 없음`과 확인 시각이 표시된다.
- **성공 기준:** 정상 쿠키로 인증 필요 VOD를 다시 분석할 수 있다. 삭제 후 인증 필요 기능은 다시 인증 필요로 표시된다.

## S01.3 사용자는 분석한 VOD를 원하는 품질로 다운로드한다

### T0108. 기본 다운로드 설정

- **입력:** 다운로드 폴더와 기본 품질.
- **동작:** 폴더 존재·쓰기 가능 여부와 품질값을 확인해 저장한다.
- **출력:** 설정 화면과 VOD 다운로드 화면에 저장 폴더와 기본 품질이 표시된다.
- **성공 기준:** 존재하고 쓰기 가능한 폴더만 저장된다. 잘못된 폴더는 이유가 표시된다. 앱을 다시 실행해도 설정값이 유지된다.

### T0109. VOD 다운로드 설정 화면

- **입력:** VOD 카드의 `다운로드 설정` 버튼과 분석한 품질 목록.
- **동작:** 품질, 전체 다운로드, 저장 폴더, 예상 파일명을 선택하는 화면을 연다.
- **출력:** 품질별 이름·해상도·프레임률·영상/음성 포함 여부와 최종 예상 경로, `다운로드 시작`, `취소`가 표시된다.
- **성공 기준:** 분석에서 실제 제공된 품질만 선택할 수 있다. 설정 화면을 여는 것만으로 작업이 시작되지 않는다. 기존 파일과 이름이 같으면 덮어쓰기·이름 변경·취소를 선택한다.

### T0110. FFmpeg 상태 확인

- **입력:** 저장된 FFmpeg 경로 또는 기본 실행 위치.
- **동작:** FFmpeg를 실행해 사용 가능 여부와 버전을 확인하고 없으면 파일 선택으로 경로를 지정할 수 있게 한다.
- **출력:** `사용 가능`, `파일 없음`, `실행 실패`, `응답 없음`, 경로·버전과 `실행 파일 선택`이 표시된다.
- **성공 기준:** FFmpeg가 필요한 VOD 작업은 사용할 수 없을 때 시작하지 않는다. 실제 FFmpeg만 저장할 수 있고 정상 경로 선택 후 다운로드를 계속할 수 있다.

### T0111. 다운로드 작업 생성

- **입력:** VOD URL, 제목, 선택 품질, 저장 폴더, 예상 파일명과 다운로드 시작 버튼.
- **동작:** VOD 작업을 생성해 작업 목록에 추가하고 yt-dlp 공식 Python API로 다운로드를 시작한다.
- **출력:** 작업 목록에 작업 ID, `VOD 다운로드`, 제목, `대기/실행 중`, 진행률, 저장 경로가 표시된다.
- **성공 기준:** 시작 버튼 한 번에 작업 하나만 생성된다. GUI가 멈추지 않는다. 동일 URL·품질·저장 경로의 진행 작업이 있으면 새 작업 대신 기존 작업을 안내한다.

### T0112. 다운로드 진행률과 완료

- **입력:** yt-dlp Python API의 진행 정보와 종료 결과.
- **동작:** 받은 용량, 전체 용량, 진행률, 속도, 남은 시간을 갱신하고 종료 후 결과 파일을 확인한다.
- **출력:** 작업 행에 진행 막대·속도·남은 시간이 표시되고 성공 시 `완료`, 파일명·크기·저장 경로가 표시된다.
- **성공 기준:** 일부 진행값을 읽지 못해도 작업은 계속된다. 외부 도구 정상 종료와 결과 파일 존재·크기 0 초과를 모두 확인한 뒤 완료로 표시한다.

### T0113. VOD 취소와 실패 재시도

- **입력:** 실행 작업의 취소 또는 실패·취소 작업의 재시도 버튼.
- **동작:** 취소 시 해당 외부 작업을 종료하고 재시도 시 기존 옵션으로 새 작업을 만든다.
- **출력:** 원 작업에는 `취소/실패`, 종료 시각·이유가 남고 재시도 작업은 새 작업 ID로 추가된다.
- **성공 기준:** 취소 후 파일 크기가 더 증가하지 않는다. 재시도가 원 작업 기록을 덮어쓰지 않는다. 인증·설정 수정이 필요한 실패는 수정 전 자동 반복하지 않는다.

# E02. 현재 라이브 방송을 수동 녹화

이 Epic이 끝나면 기존 앱에서 채널·라이브 URL을 분석하고 현재 방송을 시작·중지해 재생 가능한 파일을 얻을 수 있다.

## S02.1 사용자는 채널·라이브 URL에서 현재 방송을 확인한다

### T0201. 채널·라이브 URL 판별 추가

- **입력:** URL 입력 문자열.
- **동작:** 기존 VOD 판별에 채널 URL과 라이브 URL 판별을 추가하고 채널 ID를 추출한다.
- **출력:** 분석 중 결과 영역에 `채널 정보 확인 중` 또는 `라이브 상태 확인 중`이 표시된다.
- **성공 기준:** URL 분석은 조회만 수행한다. 분석만으로 녹화나 채널 등록이 시작되지 않는다.

### T0202. 오프라인 채널 결과

- **입력:** 채널 정보와 현재 오프라인 상태.
- **동작:** 오프라인 채널 결과 카드를 표시한다.
- **출력:** 프로필, 채널명, 팔로워 수, 상태 `오프라인`, 마지막 확인 시각이 표시된다.
- **성공 기준:** 이전 방송 제목·카테고리·시청자를 현재 정보처럼 표시하지 않는다. 녹화 시작 버튼은 표시하지 않는다.

### T0203. 라이브 방송 결과

- **입력:** 채널 정보와 현재 라이브 정보·품질 목록.
- **동작:** 현재 방송 카드를 표시한다.
- **출력:** 방송 썸네일·제목, 채널명, 카테고리, 태그, 시청자 수, 팔로워 수, 시작 시각, 품질 목록과 `녹화 설정` 버튼이 표시된다.
- **성공 기준:** 현재 방송값과 화면값이 일치한다. 정보가 없는 항목은 `확인 불가`로 표시한다. 녹화 설정 버튼을 누르기 전에는 작업이 생성되지 않는다.

### T0204. Streamlink 상태 확인

- **입력:** 저장된 Streamlink 경로 또는 기본 실행 위치.
- **동작:** Streamlink 실행 가능 여부와 버전을 확인하고 없으면 파일 선택으로 경로를 지정할 수 있게 한다.
- **출력:** 도구 상태·경로·버전, 녹화 가능 여부와 `실행 파일 선택`이 표시된다.
- **성공 기준:** 실제 Streamlink만 저장할 수 있다. 필요한 도구가 없으면 녹화를 시작하지 않고 정상 경로 선택 후 다시 진행할 수 있다.

## S02.2 사용자는 라이브 녹화를 시작하고 중지한다

### T0205. 녹화 설정 확인

- **입력:** 라이브 카드의 녹화 설정 버튼, 품질 목록, 저장 폴더.
- **동작:** 품질, 확장자, 예상 파일명과 저장 위치를 확인하는 화면을 연다.
- **출력:** 실제 제공 품질, 결과 확장자, 최종 경로와 `녹화 시작`, `취소`가 표시된다.
- **성공 기준:** 사용할 수 없는 품질·확장자는 시작 전에 안내된다. 화면을 여는 것만으로 녹화하지 않는다.

### T0206. 최신 상태 확인 후 녹화 시작

- **입력:** 녹화 시작 버튼, 채널 ID, 선택 품질·확장자·경로.
- **동작:** 최신 라이브·방송 ID를 다시 확인하고 방송 중이면 Streamlink·FFmpeg를 실행한다.
- **출력:** 작업 목록에 `실시간 녹화`, 채널·방송 제목, `녹화 중`, 시작 시각, 파일 크기·경로가 표시된다.
- **성공 기준:** 오프라인이면 프로세스를 만들지 않는다. 첫 미디어 데이터가 들어온 뒤 녹화 중으로 표시되고 파일 크기가 증가한다.

### T0207. 같은 방송 중복 녹화 방지

- **입력:** 새 녹화 요청의 채널 ID·방송 ID와 현재 녹화 작업.
- **동작:** 같은 방송 ID의 진행 작업을 찾고 있으면 새 프로세스를 시작하지 않는다.
- **출력:** 기존 작업 ID, 시작 시각과 상태가 안내되고 기존 작업 행이 선택된다.
- **성공 기준:** URL 화면과 작업 재시도에서 요청이 겹쳐도 같은 방송의 녹화 프로세스는 하나다.

### T0208. 녹화 중지와 파일 확인

- **입력:** 녹화 작업의 중지 버튼.
- **동작:** 외부 프로그램에 정상 종료를 요청하고 파일의 재생 시간·영상·음성을 확인한다.
- **출력:** 정상 파일은 `완료`와 경로·길이가 표시되고 강제 종료·마감 실패 파일은 `중단됨`과 이유가 표시된다.
- **성공 기준:** 정상 완료 파일은 재생 가능하다. 중지 버튼 반복이 상태를 여러 번 변경하지 않는다. 강제 종료 파일을 정상 완료로 표시하지 않는다.

### T0209. 작업 기록 재실행 복원

- **입력:** VOD·녹화 작업 상태와 앱 시작.
- **동작:** 완료·취소·실패·중단 작업을 저장하고 재실행 시 작업 목록에 복원한다.
- **출력:** 이전 작업의 종류, 대상, 마지막 상태, 시각, 경로와 실패 이유가 표시된다.
- **성공 기준:** 앱을 다시 실행해도 기록을 확인할 수 있다. 실제 프로세스가 없는 실행 중 작업은 `이전 실행에서 중단됨`으로 표시된다.

# E03. 관심 채널을 등록하고 수동 관리

이 Epic이 끝나면 사용자는 분석 결과에서 채널을 명시적으로 등록하고 재실행 후에도 목록에서 상태를 새로고침·검색·녹화할 수 있다.

## S03.1 사용자는 분석한 채널을 등록한다

### T0301. 채널 등록 버튼과 개념

- **입력:** 채널 또는 라이브 분석 성공 결과.
- **동작:** 결과 카드에 `채널 등록` 버튼을 추가한다. URL 분석 자체는 목록을 변경하지 않는다.
- **출력:** 미등록 채널에는 `채널 등록`, 등록 채널에는 `이미 등록됨`과 `등록 채널 보기`가 표시된다.
- **성공 기준:** 분석 전후 등록 채널 수가 같다. 사용자가 등록 버튼을 누르기 전에는 저장되지 않는다.

### T0302. 채널 등록 확인

- **입력:** 채널 등록 버튼과 채널 정보.
- **동작:** 채널명·ID, 저장 폴더, 기본 품질·확장자를 확인한다.
- **출력:** 각 값과 `등록`, `취소`가 표시된다.
- **성공 기준:** 취소하면 저장되지 않는다. 필수 설정 오류가 있으면 등록할 수 없다.

### T0303. 등록 채널 저장·복원·중복 방지

- **입력:** 유효한 등록 설정과 등록 버튼.
- **동작:** 채널 ID와 설정을 저장하고 앱 시작 시 복원한다.
- **출력:** 등록 채널 표에 채널명, 현재 상태와 마지막 수동 확인 시각이 표시된다.
- **성공 기준:** 같은 채널 ID는 한 행만 존재한다. 앱 재실행 후 채널과 설정이 유지된다.

## S03.2 사용자는 등록 채널을 조회·수정·삭제한다

### T0304. 등록 채널 수동 새로고침

- **입력:** 선택 채널 또는 전체 새로고침 버튼.
- **동작:** 채널의 라이브·제목·카테고리·시청자 정보를 다시 조회한다.
- **출력:** 채널 표에 최신 방송 정보, 상태, 마지막 확인 시각이 표시된다.
- **성공 기준:** 자동 확인을 끈 채널도 수동으로 갱신된다. 한 채널 실패가 다른 채널 갱신을 막지 않는다.

### T0305. 등록 채널 수동 녹화

- **입력:** 등록 채널의 녹화 버튼.
- **동작:** 최신 라이브를 확인하고 E02의 녹화 설정·시작 흐름을 사용한다.
- **출력:** 오프라인 안내 또는 녹화 설정 화면이 표시된다.
- **성공 기준:** 별도 녹화 구현을 만들지 않고 기존 수동 녹화와 같은 작업 상태·중복 방지·중지를 사용한다.

### T0306. 채널 설정 수정

- **입력:** 등록 채널과 새 표시 이름·폴더·품질·확장자·자동 설정.
- **동작:** 입력을 확인하고 저장 시 채널 설정을 갱신한다.
- **출력:** 채널 행과 상세 화면에 새 설정이 표시된다.
- **성공 기준:** 취소하면 기존 값이 유지된다. 새 설정은 다음 작업부터 적용되고 실행 중 작업은 바뀌지 않는다.

### T0307. 채널 삭제

- **입력:** 채널 삭제와 진행 중 녹화 여부.
- **동작:** 녹화가 있으면 `중지 후 삭제`, `녹화 유지 후 목록 삭제`, `취소`를 제공한다.
- **출력:** 선택에 따라 채널 행이 제거되고 녹화가 중지되거나 유지된다.
- **성공 기준:** 취소는 아무것도 변경하지 않는다. 과거 작업 기록의 채널명은 유지된다.

### T0308. 채널 검색과 상태 필터

- **입력:** 검색어와 전체·라이브·오프라인·녹화 중·오류 필터.
- **동작:** 채널명·방송 제목 검색과 상태 조건을 함께 적용한다.
- **출력:** 일치 채널과 `전체 N개 중 M개`가 표시된다.
- **성공 기준:** 검색과 필터를 함께 사용하면 두 조건을 모두 만족한 채널만 보인다. 필터된 행의 작업 버튼이 정확한 채널에 적용된다.

# E04. 등록 채널 자동 확인과 조건 녹화

이 Epic이 끝나면 자동 확인을 켠 등록 채널만 주기적으로 갱신되고, 자동 녹화까지 켠 채널은 조건에 맞을 때 기존 녹화 흐름으로 녹화된다.

## S04.1 사용자는 등록 채널의 상태를 자동으로 갱신한다

### T0401. 자동 확인 주기와 활성 상태

- **입력:** 기존 등록 채널, 기본·채널별 확인 주기, 자동 상태 확인 체크와 자동 녹화 체크.
- **동작:** 등록·수정 화면에 두 자동 설정을 추가하고 양수 주기를 저장한다. 자동 녹화를 켜면 자동 상태 확인도 켠다.
- **출력:** 채널 행에 자동 확인·자동 녹화 상태와 마지막·다음 확인 시각이 표시된다.
- **성공 기준:** 자동 확인을 끈 채널은 자동 조회하지 않는다. 0·음수 주기는 저장되지 않는다.

### T0402. 주기적 채널 조회

- **입력:** 자동 확인 활성 채널과 현재 시각.
- **동작:** 확인 시각이 된 채널을 조회하고 라이브·제목·카테고리·태그·시청자 정보를 갱신한다.
- **출력:** 최신 상태와 조회 실패 여부가 채널 행에 반영된다.
- **성공 기준:** 같은 채널 조회가 겹치지 않는다. 한 채널 실패가 다른 채널 확인을 중단시키지 않는다.

### T0403. 라이브 시작·종료와 카테고리 변경 감지

- **입력:** 이전 정상 상태와 최신 정상 조회 결과.
- **동작:** 오프라인↔라이브와 라이브 중 카테고리 변경을 비교한다.
- **출력:** 채널 상세의 최근 상태 변경 목록에 이전·새 상태 또는 카테고리와 확인 시각이 한 번 기록된다.
- **성공 기준:** 동일 상태 반복은 이벤트를 만들지 않는다. 조회 오류·누락값을 종료나 변경으로 오인하지 않는다.

## S04.2 사용자는 자동 녹화 조건을 설정한다

### T0404. 카테고리·태그 조건

- **입력:** 포함·제외 카테고리, 포함·제외 태그와 현재 방송 정보.
- **동작:** 제외 조건을 우선 적용하고 포함 조건 충족 여부를 계산한다.
- **출력:** 일치·제외한 항목과 `녹화 대상/제외` 결과가 표시된다.
- **성공 기준:** 제외 하나라도 일치하면 녹화하지 않는다. 포함 목록이 비어 있을 때의 결과가 화면 설명과 일치한다.

### T0405. 시청자·팔로워·시간 조건

- **입력:** 최소·최대 시청자, 최소 팔로워, 허용 요일·시간과 현재 값.
- **동작:** 각 활성 조건을 비교해 항목별 결과를 계산한다.
- **출력:** 실제 값, 기준값, 충족·불충족과 최종 결과가 표시된다.
- **성공 기준:** 최소·최대와 같은 값의 포함 여부가 명확하다. 최소>최대는 저장되지 않는다. 자정을 넘는 시간 범위를 처리한다.

### T0406. 조건 미리보기

- **입력:** 편집 중인 조건과 현재 방송 또는 예시값.
- **동작:** 실제 자동 녹화와 같은 조건 판단을 실행한다.
- **출력:** `자동 녹화/녹화하지 않음`과 항목별 이유가 표시된다.
- **성공 기준:** 저장 후 같은 입력의 실제 판단과 미리보기 결과가 같다.

## S04.3 사용자는 조건 일치 방송을 자동 녹화한다

### T0407. 자동 녹화 시작

- **입력:** 오프라인→라이브 변화, 자동 녹화 활성, 조건 일치와 방송 ID.
- **동작:** 채널 설정으로 E02의 녹화 작업을 생성한다.
- **출력:** 작업 상세에 `자동 녹화`, 적용 조건과 방송 ID가 표시된다.
- **성공 기준:** 자동 상태 확인만 켠 채널은 녹화하지 않는다. 자동 녹화까지 켜고 조건이 맞은 채널만 시작한다.

### T0408. 자동·수동 중복 방지

- **입력:** 같은 방송 ID의 자동·수동 시작 요청과 현재 작업.
- **동작:** 기존 녹화가 있으면 새 프로세스를 만들지 않는다.
- **출력:** 기존 작업 ID와 시작 원인이 안내된다.
- **성공 기준:** 같은 방송에는 녹화 프로세스가 하나만 존재한다. 새 방송 ID는 이전 작업 종료 후 시작할 수 있다.

# E05. 여러 작업과 네트워크 사용량 제어

이 Epic이 끝나면 현재 앱에서 여러 VOD·녹화 작업을 제한된 개수로 실행하고 연결 수·속도·프록시를 설정할 수 있다.

## S05.1 사용자는 여러 작업을 한 목록에서 제어한다

### T0501. 작업 목록 상세와 재시도

- **입력:** VOD·녹화 작업과 상태 변경.
- **동작:** 종류, 대상, 상태, 진행률, 시각, 경로, 실패 이유를 한 표에 표시하고 실패 작업 재시도를 제공한다.
- **출력:** 최신순 작업 행과 작업 상세가 표시된다.
- **성공 기준:** 재시도는 원 기록을 유지하고 새 작업을 만든다. 파일이 이동·삭제돼도 기록은 유지하고 파일 없음으로 표시한다.

### T0502. 전체·종류별 동시 실행 제한

- **입력:** 전체, VOD, 녹화, 후처리 한도와 대기 작업.
- **동작:** 전체 한도와 종류 한도를 모두 만족할 때 다음 작업을 시작한다.
- **출력:** 종류별 `실행 N/한도 M`, 대기 순서와 대기 이유가 표시된다.
- **성공 기준:** 실행 수가 한도를 넘지 않는다. 하나가 끝나면 가능한 다음 대기 작업이 시작된다. 한도를 낮춰도 실행 중 작업을 강제 종료하지 않는다.

## S05.2 사용자는 연결 수·속도·프록시를 설정한다

### T0503. 최대 연결 수와 속도 제한

- **입력:** 작업당 연결 수, 전체·작업별 속도와 단위.
- **동작:** 정상값을 지원 외부 도구 실행에 적용한다.
- **출력:** 작업 시작 전에 실제 적용 연결 수와 속도 또는 `지원하지 않음`이 표시된다.
- **성공 기준:** 0·음수·잘못된 단위는 저장되지 않는다. 지원하지 않는 도구에 적용된 것으로 표시하지 않는다.

### T0504. 프록시 설정과 연결 확인

- **입력:** 직접·시스템·사용자 지정 방식, scheme·host·port와 선택 인증값.
- **동작:** 입력을 확인하고 치지직 조회 연결을 시험한 뒤 저장한다.
- **출력:** 연결 성공·실패, 응답 시간과 실패 이유가 표시된다.
- **성공 기준:** 실패한 시험이 기존 정상 설정을 덮어쓰지 않는다. 정상 프록시는 정보 조회와 지원 작업에 적용된다.

### T0505. GoodbyeDPI 선택 실행

- **입력:** 실행 파일 경로와 사용자의 시작·중지 선택.
- **동작:** 사용자가 시작한 경우에만 실행하고 프로그램이 시작한 프로세스만 중지한다.
- **출력:** `사용 안 함/중지/실행 중/실패`가 표시된다.
- **성공 기준:** 기본 상태에서는 실행되지 않는다. 실패가 다른 네트워크 기능을 종료시키지 않는다.

# E06. VOD·녹화 세부 제어

이 Epic이 끝나면 기존 다운로드·녹화 흐름에서 구간, 분할, 이어받기, 녹화 형식과 재연결을 사용할 수 있다.

## S06.1 사용자는 VOD 구간과 분할 방식을 선택한다

### T0601. 구간 다운로드

- **입력:** 시작·종료 시각과 VOD 전체 길이.
- **동작:** `0 ≤ 시작 < 종료 ≤ 전체 길이`를 확인해 기존 다운로드 작업에 구간을 적용한다.
- **출력:** 선택 구간·길이와 구간 결과 파일이 표시된다.
- **성공 기준:** 잘못된 시간은 시작 전에 거부된다. 결과 길이가 요청 구간과 허용 오차 안에 있다.

### T0602. 시간·용량 기준 분할

- **입력:** 대상 구간과 시간 간격 또는 목표 용량.
- **동작:** 조각 범위를 계산해 순번이 있는 파일을 생성한다.
- **출력:** 예상·실제 조각 수와 조각별 시간·크기·경로가 표시된다.
- **성공 기준:** 값은 0보다 커야 한다. 모든 조각을 순서대로 재생하면 대상 전체 범위를 덮는다.

### T0603. 중복·부분 파일 처리

- **입력:** URL·품질·구간·경로와 기존 진행 작업·부분 파일.
- **동작:** 동일 진행 작업은 막고 부분 파일은 이어받기·처음부터·취소를 선택한다.
- **출력:** 기존 작업 또는 부분 파일 크기와 가능한 행동이 표시된다.
- **성공 기준:** 동일 진행 작업은 하나다. 불완전 파일은 완료로 표시되지 않고 확인 없이 삭제되지 않는다.

## S06.2 사용자는 녹화 품질·형식과 끊김 처리를 설정한다

### T0604. 채널별 품질·확장자·파일명

- **입력:** 전역·채널 품질, 확장자, 채널명·제목·날짜·방송 ID 파일명 형식.
- **동작:** 채널 설정을 우선 적용하고 실제 품질·형식·파일명을 결정한다.
- **출력:** 녹화 전에 실제 적용값과 최종 경로가 표시된다.
- **성공 기준:** 결과 해상도와 컨테이너가 적용값과 일치한다. 금지 문자를 처리하고 기존 파일을 자동 덮어쓰지 않는다.

### T0605. 연결 끊김 감지와 제한 재연결

- **입력:** 마지막 데이터 시각, 최신 라이브 상태, 최대 횟수와 간격.
- **동작:** 방송 종료와 연결 실패를 구분하고 라이브이면 새 스트림으로 제한 재연결한다.
- **출력:** `방송 종료/연결 끊김/재연결 N/M`, 다음 시도와 조각 파일이 표시된다.
- **성공 기준:** 방송 종료에는 재연결하지 않는다. 최대 횟수를 넘지 않고 무한 대기하지 않는다.

### T0606. 반복 시작·중지 확인

- **입력:** 같은 테스트 방송의 시작·중지 반복.
- **동작:** 작업별 외부 프로세스와 파일을 종료하고 다음 작업을 시작한다.
- **출력:** 반복마다 별도 작업 ID·상태·파일이 표시된다.
- **성공 기준:** 10회 반복 후 새 녹화를 시작할 수 있고 종료 프로세스가 남거나 작업 상태가 섞이지 않는다.

# E07. 미등록 방송을 조건으로 발견하고 녹화

이 Epic이 끝나면 사용자는 등록하지 않은 현재 방송을 조건으로 찾고 한 번 녹화·채널 등록·무시를 선택할 수 있다.

## S07.1 사용자는 현재 방송을 조건으로 찾는다

### T0701. 현재 방송 목록 조회·중지

- **입력:** 탐색 시작·중지, 자동 탐색 간격과 최대 조회 수.
- **동작:** 현재 방송을 페이지별로 가져오고 방송 ID 중복을 제거하며 중지 시 다음 페이지 요청을 멈춘다.
- **출력:** 현재 페이지, 받은 방송 수, 마지막·다음 탐색 시각이 표시된다.
- **성공 기준:** 마지막 페이지에서 끝나고 같은 방송은 한 행만 표시된다. 이전 탐색과 겹치지 않는다.

### T0702. 탐색 조건 저장과 적용

- **입력:** 조건 이름, 카테고리, 포함·제외 태그, 최소·최대 시청자, 최소 팔로워.
- **동작:** 조건을 저장하고 방송별 일치 여부와 이유를 계산한다.
- **출력:** 조건 목록과 일치 방송의 실제값·기준값·일치 이유가 표시된다.
- **성공 기준:** 제외 조건을 우선한다. 최소·최대와 같은 값의 포함 여부가 명확하다. 앱 재실행 후 조건이 유지된다.

## S07.2 사용자는 발견 방송의 녹화 여부를 선택한다

### T0703. 발견 목록과 순차 팝업

- **입력:** 처음 조건에 일치한 방송.
- **동작:** 목록에 추가하고 표시 중 팝업이 없을 때만 새 팝업을 연다.
- **출력:** 썸네일, 제목, 채널, 카테고리, 태그, 시청자, 팔로워, 일치 이유와 행동 버튼이 표시된다.
- **성공 기준:** 팝업은 한 번에 하나다. 닫은 방송도 발견 목록에서 다시 볼 수 있다.

### T0704. 한 번 녹화·등록 후 녹화·무시

- **입력:** 사용자의 행동 선택과 방송·채널 정보.
- **동작:** 최신 라이브를 다시 확인해 기존 녹화·채널 등록 흐름을 실행하거나 선택 범위로 무시한다.
- **출력:** 생성된 작업·채널 또는 무시 종류와 만료 시각이 표시된다.
- **성공 기준:** 채널·작업 중복을 만들지 않는다. 같은 방송 팝업은 제한 시간 안에 반복되지 않고 새 방송 ID는 정상 알린다.

# E08. 앱·데스크톱·메신저 알림

이 Epic이 끝나면 기존 라이브·카테고리·작업 이벤트가 사용자가 선택한 알림 수단으로 전달된다.

## S08.1 사용자는 앱과 데스크톱에서 이벤트를 확인한다

### T0801. 앱 내부 알림 목록

- **입력:** 라이브 시작·종료, 카테고리 변경, 작업 완료·실패, 공간 부족 이벤트.
- **동작:** 읽음 상태와 관련 채널·작업을 가진 알림을 만든다.
- **출력:** 시각, 종류, 제목, 요약, 읽음 여부와 관련 화면 열기가 최신순으로 표시된다.
- **성공 기준:** 새 알림 수가 읽지 않은 수와 같다. 같은 이벤트가 중복 생성되지 않는다.

### T0802. 데스크톱 팝업과 행동

- **입력:** 데스크톱 알림이 활성화된 이벤트와 사용자의 녹화·보기·무시 선택.
- **동작:** 운영체제 알림을 표시하고 행동 시 최신 상태를 다시 확인한다.
- **출력:** 앱 밖에서도 사건 종류와 대상이 보이고 선택 결과가 앱에 반영된다.
- **성공 기준:** 오래된 팝업으로 오프라인 방송 녹화를 만들지 않는다. OS 알림 실패 시 앱 내부 알림은 유지된다.

## S08.2 사용자는 Telegram·Discord로 선택 이벤트를 받는다

### T0803. Telegram 설정과 이벤트 전송

- **입력:** bot token, chat ID, 시험·실제 이벤트.
- **동작:** 시험 성공 설정을 저장하고 선택 이벤트를 메시지로 보낸다.
- **출력:** 시험·전송 성공 또는 인증·chat·제한·네트워크 오류가 표시된다.
- **성공 기준:** 실패 설정이 정상 설정을 덮어쓰지 않는다. 전송 실패가 원래 작업 상태를 실패로 바꾸지 않는다.

### T0804. Discord 설정과 이벤트 전송

- **입력:** webhook과 시험·실제 이벤트.
- **동작:** 시험 성공 webhook을 저장하고 길이·mention을 처리해 메시지를 보낸다.
- **출력:** 시험·전송 결과와 Discord 메시지가 표시된다.
- **성공 기준:** 긴 제목 때문에 전체 전송이 실패하지 않고 `@everyone/@here`가 전체 mention을 발생시키지 않는다.

### T0805. 이벤트별 수단 선택과 실패 재전송

- **입력:** 이벤트별 앱·데스크톱·Telegram·Discord 체크와 실패 알림 재전송.
- **동작:** 활성 수단에만 한 번 전달하고 실패는 수동 재시도한다.
- **출력:** 수단별 전송 상태, 마지막 시각·시도 횟수가 표시된다.
- **성공 기준:** 비활성 수단은 호출하지 않는다. 재전송 성공 시 상태가 갱신되고 무한 자동 재시도하지 않는다.

# E09. 녹화 결과 후처리와 파일 관리

이 Epic이 끝나면 사용자는 기존 녹화 파일을 확인·병합·변환·인코딩·분할·이동하고 목록에서 관리할 수 있다.

## S09.1 사용자는 녹화 결과를 확인하고 조각을 병합한다

### T0901. 결과 파일 상태 확인

- **입력:** 완료·중단 작업의 결과 경로.
- **동작:** 파일 존재·크기·재생 시간·영상·음성을 확인한다.
- **출력:** `정상/파일 없음/0바이트/읽기 실패/영상 없음/음성 없음`과 상세값이 표시된다.
- **성공 기준:** 파일 존재만으로 정상 판정하지 않고 확인 실패가 원본을 변경하지 않는다.

### T0902. 조각 순서 확인과 병합

- **입력:** 같은 작업의 조각 순번·시각·파일과 결과 경로.
- **동작:** 누락·중복·손상을 확인해 정상 조각을 순서대로 병합하고 결과를 다시 확인한다.
- **출력:** 조각 표, 병합 진행률, 결과 재생 시간·경로가 표시된다.
- **성공 기준:** 문제 조각이 있으면 병합하지 않는다. 결과 확인 전 원본을 삭제하지 않고 실패 시 모두 유지한다.

## S09.2 사용자는 결과를 변환·분할·정리한다

### T0903. 컨테이너 변환과 인코딩

- **입력:** 원본, 목표 컨테이너, 영상·음성 codec과 품질 설정.
- **동작:** 호환 시 stream copy, 그 외 인코딩을 실행하고 진행률을 표시한다.
- **출력:** 처리 방식, 진행률, 결과 codec·컨테이너·재생 시간이 표시된다.
- **성공 기준:** 실제 결과 형식이 선택값과 일치한다. 취소·실패 시 불완전 파일을 완료로 표시하지 않고 원본을 유지한다.

### T0904. 후처리 분할·이동·공간 확인

- **입력:** 결과 파일, 시간·용량 분할값, 폴더 규칙과 남은 공간.
- **동작:** 공간을 먼저 확인하고 분할한 뒤 채널·날짜·작업 종류 폴더로 이동한다.
- **출력:** 예상 공간, 조각 목록, 이동 전·후 경로가 표시된다.
- **성공 기준:** 공간 부족 시 시작하지 않는다. 전체 재생 범위를 빠뜨리지 않고 이동 실패 시 원본 위치를 유지한다.

### T0905. 생성 파일 목록과 삭제

- **입력:** 작업 결과·조각·부분 파일과 삭제 선택.
- **동작:** 파일명·크기·길이·상태를 표시하고 진행 중 파일을 제외한 선택 파일을 확인 후 삭제한다.
- **출력:** 파일 목록, 폴더 열기, 삭제 대상·전체 크기와 처리 결과가 표시된다.
- **성공 기준:** 취소하면 삭제하지 않는다. 선택 밖 파일과 진행 중 파일을 삭제하지 않는다.

# E10. 시스템 상태와 백그라운드 실행

이 Epic이 끝나면 사용자는 현재 앱의 자원 상태를 보고 공간 부족을 처리하며 tray에서 기존 작업을 계속할 수 있다.

## S10.1 사용자는 PC와 저장 공간 상태를 확인한다

### T1001. CPU·메모리·네트워크·디스크 표시

- **입력:** 시스템과 앱 프로세스의 CPU·메모리, 송수신 누적량, 저장 폴더 드라이브 값.
- **동작:** 설정 간격마다 사용률·속도·용량을 계산한다.
- **출력:** 전체·앱 CPU, 전체·앱 메모리, 다운로드·업로드 속도, 드라이브 전체·남은 공간과 갱신 시각이 표시된다.
- **성공 기준:** 조회 실패 항목만 `확인 불가`로 표시하고 다른 값과 작업은 계속 갱신된다.

### T1002. 공간 부족 경고

- **입력:** 새 작업 대상 드라이브 남은 공간과 최소 여유 공간.
- **동작:** 작업 시작 전에 비교해 기준 이하이면 확인창을 표시한다.
- **출력:** 작업 종류, 남은 공간, 최소 요구량과 `그래도 시작/취소`가 표시된다.
- **성공 기준:** 사용자 선택 전 작업을 만들지 않는다. 진행 중 녹화를 예고 없이 강제 종료하지 않는다.

## S10.2 사용자는 앱을 tray에서 계속 실행하고 안전하게 종료한다

### T1003. Tray 최소화와 복원

- **입력:** tray로 보내기와 tray 메뉴의 열기.
- **동작:** 기존 창을 숨기고 복원한다.
- **출력:** tray 메뉴에 열기, 실행 작업 수, 종료가 표시된다.
- **성공 기준:** tray에서도 자동 확인과 작업이 계속되고 복원 시 창이 여러 개 생기지 않는다.

### T1004. 작업 중 종료 선택과 프로세스 정리

- **입력:** 작업 중 창 닫기와 `계속/중지 후 종료/취소` 선택.
- **동작:** 선택에 따라 tray 유지 또는 프로그램이 시작한 외부 작업 종료와 상태 저장을 수행한다.
- **출력:** 실행 작업 수와 정리 상태가 표시되고 다음 실행 시 중단 작업이 표시된다.
- **성공 기준:** 취소는 상태를 유지한다. 앱 소유 프로세스만 종료하고 사용자가 별도 실행한 프로세스는 건드리지 않는다.

# E11. 도구 갱신·플러그인·오류 복구

이 Epic이 끝나면 사용자는 개인 PC의 외부 도구를 갱신하고 선택 플러그인을 사용하며 주요 오류 후 기존 앱을 계속 사용할 수 있다.

## S11.1 사용자는 외부 도구 경로와 버전을 관리한다

### T1101. 외부 도구 통합 설정

- **입력:** FFmpeg·Streamlink 실행 파일 선택과 앱에 포함된 yt-dlp Python 패키지.
- **동작:** 외부 실행 파일은 종류·실행 가능·버전을 확인해 정상 경로만 저장하고, yt-dlp는 설치된 패키지 버전과 상태를 확인한다.
- **출력:** 외부 도구별 경로·버전·상태와 yt-dlp 패키지 버전·상태, 각 도구를 사용하는 기능이 표시된다.
- **성공 기준:** 다른 종류·실행 불가 외부 파일은 저장되지 않고 다음 작업은 선택 경로를 사용한다. yt-dlp는 사용자가 실행 파일 경로를 선택하지 않으며 앱에 포함된 Python 패키지를 사용한다.

### T1102. 외부 도구 갱신

- **입력:** 갱신 도구 선택.
- **동작:** 새 파일을 준비하고 사용 중이 아닐 때 교체한 뒤 버전을 다시 확인한다.
- **출력:** 진행 상태와 갱신 전·후 버전 또는 실패 이유가 표시된다.
- **성공 기준:** 사용 중 도구를 교체하지 않는다. 갱신 실패 시 기존 실행 가능 도구를 계속 사용한다.

## S11.2 사용자는 선택형 플러그인을 켜고 끈다

### T1103. 플러그인 목록과 작업 완료 플러그인

- **입력:** 확인 가능한 Python 플러그인과 활성 선택, 완료 작업 정보.
- **동작:** 플러그인을 켜고 끄며 예제 플러그인은 완료 결과 옆에 요약 텍스트를 만든다.
- **출력:** 이름, 설명, 활성 상태, 마지막 결과와 생성 요약 파일이 표시된다.
- **성공 기준:** 활성 플러그인만 실행되고 앱 재실행 후 상태가 유지된다. 실패·취소 작업에는 요약을 만들지 않는다.

### T1104. 플러그인 오류 분리

- **입력:** 플러그인 예외·시간 초과.
- **동작:** 해당 플러그인만 실패 처리한다.
- **출력:** 원 작업 완료와 플러그인 실패·이름·오류가 별도로 표시된다.
- **성공 기준:** 플러그인 오류가 원 작업과 다른 작업 상태를 바꾸거나 GUI를 멈추지 않는다.

## S11.3 사용자는 실패 원인을 확인하고 복구한다

### T1105. 작업 오류 상세와 재시도

- **입력:** 네트워크, 인증, 설정, 공간, 외부 도구 실패.
- **동작:** 오류 종류·대상·시각·요약·수정 행동과 재시도 가능 여부를 표시한다.
- **출력:** 오류 상세와 설정 열기·다시 시도 버튼이 표시된다.
- **성공 기준:** 사용자가 확인할 항목을 구분할 수 있고 재시도는 원 기록을 유지한 새 작업으로 생성된다.

### T1106. 저장 데이터 오류와 반복 조작 복구

- **입력:** 읽을 수 없는 설정·채널·작업 데이터 또는 시작·취소·재시도 연속 클릭.
- **동작:** 읽을 수 있는 데이터로 앱을 시작하고 처리 중 중복 행동을 막는다.
- **출력:** 읽지 못한 데이터 종류·영향 범위와 한 작업당 하나의 현재 상태가 표시된다.
- **성공 기준:** 한 데이터 오류 때문에 앱 전체가 시작 실패하지 않는다. 화면 실행 작업 수와 실제 관리 프로세스 수가 일치한다.
